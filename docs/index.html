v0.4.0Native ESM · no runtime dependencies · ukulele & guitar

Turn a score into music your hands can play

on a high-G ukulele on a six-string guitar without dropping a note at the tempo you choose for the player you are

scorify finds a string, a fret and a finger for every note of a score, and checks every result again before returning it. It keeps sounding pitch, note spelling and exact musical time. When a tune can't be played under the limits you set, it tells you whether it proved that or ran out of search budget. Then it can strum and play the result with a plucked-string synthesizer.

Built by Aron Homberg (kyr0) (opens in a new tab)

🎼

Exact musical time

Onsets and durations are rational quarter notes, so q(1, 3) is an exact triplet. Rests, ties, holds, tempo, meter and key maps all keep their source identities.

🖐️

Fingerings, not just frets

Four fretting fingers, open strings, barres, held notes and hand shifts. A pitch that fits on a string is not yet a playable fingering, so scorify checks both.

🎚️

Editable difficulty levels

Seven levels, from baby to maestro, set limits on fret span, shift speed, attacks per second and barres. You can override each limit.

⚖️

Honest results

infeasible means the search proved there is no solution within the model. search-exhausted means it ran out of budget first. optimality says whether the result is proven best or only the best one found.

🪕

Plucked-string sound

Optional waveguide synthesis with seeded humanization and strums in physical string order, including high-G. Plays through an AudioWorklet or renders offline to WAV.

🧩

Plain modules

TypeScript source, browser-native ESM and explicit subpath exports. The core has no DOM. Searches can run in a module worker, and starting a new search cancels the previous one.

🎸 Seven difficulties, eight instruments

Pick a song, a scale or one of the Billboard charts' most common chord progressions, then an instrument and a difficulty. The sample accompaniments have seven versions, from baby to maestro; imported scores use their available editions and show vocal pitches and lyrics when present. scorify fingers the accompaniment for the chosen instrument (concert ukulele with high or low G, baritone ukulele, guitar in standard or drop D, 7- and 8-string guitar, mandolin) and checks that it plays.

A scale in even notes, the last one held to the bar line, with the Beat on; or, for a seven-note scale, its chords strummed or as arpeggios. Key, Time and Play below set the tonic, the time signature and how it is played. scorify spells every degree, starts at the lowest octave the neck holds up to its highest fret, and fingers the scale for the difficulty as written, or says why it cannot.

Twenty-five chord progressions chosen for recognizability, harmonic variety and practice value: pop and rock loops, minor and Dorian progressions, borrowed chords and secondary dominants, jazz ii–V–I, longer sequences and the 12-bar blues, with how many of 739 Billboard Hot 100 songs from 1958 to 1991 start a phrase with each. A bar per chord unless the progression says otherwise (three chords in four bars, the blues in twelve), strummed or as an arpeggio, seven versions per time signature, or in a strumming pattern: the island strum, reggae skank, boom-chick, a waltz, a blues shuffle and more; Key, Time, Play and Pattern below set the key, the time signature, how it is played and the pattern. The small buttons by each chord name in the tab turn that chord to its next inversion, or back.

Counted by scorify's own script over the chord annotations of the McGill Billboard corpus (opens in a new tab) (Burgoyne, Wild and Fujinaga 2011; CC0): songs with a phrase that starts with the progression's chords (sevenths counted as triads), and for the 12-bar blues, songs with a 12-bar blues chorus. The corpus ends in 1991, before I–V–vi–IV and many minor pop loops became common in hits; a progression it does not contain shows no count. Other sources are linked, not counted.

    About this arrangement

    A difficulty is an editable, uncalibrated policy of scorify (player: { level }): limits on fret span, shift speed, attacks per second, notes at once and barres. A fingering that is valid in the model may still be uncomfortable for you. The versions and their chord shapes come from the demo (docs/assets/songs.mjs); scorify judges each shape, then fingers the version in exact mode, so it never drops, moves or shortens one of its notes. Only when no version plays does it simplify one in adaptive mode, and says above what it left out.

    
      
    

      
    
        
    Hand-authored versions: chord charts and rhythm patterns. House of the Rising Sun's tune and words are traditional; no other melody or lyrics are transcribed.

        How it works
        
    💡 From musical intent to a playable path
    
        
    You describe the music. scorify searches note positions and fingerings together, under the instrument and player limits you choose. Only a path that passes an independent replay check is returned. Musical fidelity always ranks first; comfort only decides between equally faithful arrangements.
    
      
    
    
    
    
    
      
      
        
    1. 
          01
          
      
            
      Describe
      
            
      createScore(notes, maps) takes sounding pitches, exact rational time, voices, roles, rests and ties. Each note keeps its id, so every later result can point back to the note it came from.
      
          
      
        
      2. 
        
    2. 
          02
          
      
            
      Transform
      
            
      Transpose by a spelled interval such as 2M and scale or set the tempo. Note spelling, key and chord symbols are transposed with it. Every change is logged as an edit, with its reason and the permission that allowed it.
      
          
      
        
      3. 
        
    3. 
          03
          
      
            
      Search
      
            
      At every attack, list the string positions and four-finger assignments. Then search for a path through them, using beam search, exact dynamic programming or an exhaustive reference. Strings stay in physical order, and the capo is part of the model.
      
          
      
        
      4. 
        
    4. 
          04
          
      
            
      Validate
      
            
      A separate validator rebuilds the sounding notes from the output. It checks every attack, hold, finger contact, player limit and transition before arrange() returns success.
      
          
      
        
      5. 
        
    5. 
          05
          
      
            
      Perform
      
            
      createPerformance() adds strums and seeded humanization, then checks the timing against the chosen fingering. If the timing doesn't fit, it reduces the timing variation or reports the problem. It never changes the fingering to make playback work.
      
          
      
        
      6. 
      
    
      
    
        
    
          
    Every result says what it guarantees
    
          
    result.status separates a proof from a budget limit. A partial path is never returned as a success.
    
        
    
        
    
          
    
            
    success
    Output score, fingerings, edits, source mapping, difficulty components and search statistics.
    
            
    infeasible
    The search proved that no path exists within this finite model.
    
            
    search-exhausted
    Pruning or a resource limit stopped the search first. A solution may still exist.
    
            
    cancelled
    An AbortSignal or a newer worker request stopped the search.
    
            
    unsupported
    A note asks for a technique v0.2 does not model, such as a bend or a harmonic.
    
            
    optimality
    proven-in-model only when nothing was pruned; otherwise best-found.
    
          
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    
        API
        
    📚 Plain data in, plain data out
    
        
    Scores, options and results are serializable objects. Root exports cover the score and arrangement API. Workers and audio come from explicit subpaths, so audio code stays out of the core module graph. The full contract is in the implementation specification.
    
      
    
    
    

    
    
      
    
        
        
        
        
      
    

      
    
        
    
          
    
            
    FunctionReturnsSemantics
    
            
              
    createScore(notes, options?)ScoreValidates and normalizes notes, rests and maps. Defaults to 120 quarter BPM, 4/4 and A=440. A key is never inferred.
    
              
    parsePitch("F#3"), q(n, d)Pitch, QA spelled sounding pitch, and an exact rational time in quarter notes.
    
              
    arrange(score, options)ArrangeResultJoint edit and fingering search, followed by an independent replay check.
    
              
    arrangeAsync(score, options, hooks?)PromiseCooperative scheduling with signal, onProgress and yieldEvery.
    
              
    createWorkerClient(worker)clientarrange() in a module worker. A newer request cancels the previous one, and stale replies are ignored.
    
              
    createArrangementSession(score)sessionRecomputes from the original score each time, with an LRU cache of results.
    
              
    transformScore(score, options){ score, edits }Spelled transposition and tempo scaling, with no instrument involved.
    
              
    analyzeHarmony(score)spansChord candidates per window, including arpeggios. Sparse evidence stays unknown.
    
              
    quantizePerformance(notes, maps)resultQuantizes timed performance notes against a known tempo and meter map.
    
              
    validateFrettedArrangement(…)reportThe public replay validator, for checking any fretted output.
    
              
    createPerformance(result, instrument, options?)PerformanceResultStrums, humanization and timing validation, run before any synthesis.
    
              
    createAudioPlayer(context), renderPerformance(plan)player, samplesAudioWorklet playback and offline rendering. The worklet and offline paths produce matching samples. encodeWav() writes the bytes.
    
                
          
    
        
    
      
    

      
    
        
    arrange(score, options) takes an instrument. Every other key is optional.
    
        
    
          
    
            
    KeyDefaultMeaning
    
            
              
    instrumentrequiredconcertUkulele({ tuning }), classicalGuitar({ capoFret }) or createFrettedInstrument(id, name, tuning). Strings are listed from the bass edge to the treble edge.
    
              
    mode"exact""exact" keeps transformed pitches, onsets and holds. "adaptive" may also make the edits you permit. "unconstrained" transforms without an instrument.
    
              
    transformnone{ interval: "2M" }, { tempoScale: 0.75 } or { quarterBpm: 90 }.
    
              
    player{ level: "maestro" }A level plus complexity, flexibility and overrides, such as maxFretSpan, allowBarre or rightHand.
    
              
    adaptationornaments onlyPermissions: allowOctaveShift, allowAccompanimentOmission, allowRhythmSimplification and allowHoldShortening. Note locks and protectedNoteIds protect material.
    
              
    searchbeam 64strategy: "beam" | "exact" | "exhaustive", beamWidth, maxCandidatesPerFrame and maxExpandedStates.
    
              
    autoTempofalseLowers the fastest tempo segment to the level's suggested ceiling. It never speeds a score up.
    
              
    signal, scoringnoneCancellation, and an optional pure cost hook that can never override hard validity or fidelity.

        Install
        
    🧑‍💻 Add it to your app
    
        
    Install scorify from npm, or load it from a CDN in a page with no bundler. The score-import skill installs into Claude Code or Codex with one command.
    
      
    
    
    
    
    
      
    
        
    From npm
    
        
    scorify (opens in a new tab) is plain ESM with TypeScript declarations and no runtime dependencies. Bundlers and Node resolve import … from "scorify" and its subpaths, such as scorify/worker and scorify/audio.
    
        
        
    To work on scorify itself, clone the repository (opens in a new tab) and run bun install --frozen-lockfile && bun run check (Bun 1.3.9, Node 24).
    
      
    
      
    
      
    
      
    
        
    In the browser, no bundler
    
        
    An import map loads the modules from a CDN, and each entry fetches its shared chunks from there. A Worker or an AudioWorklet must come from your page's own origin: copy the whole dist/ folder of the package next to your page for those, and pass workletUrl to the audio player. This page loads its own copy of dist/ the same way.
    
        
      
    
    
    

    
    
      
    Use it
    
      
    Pitches are sounding pitches and time is counted in quarter notes. Check result.status before you read a fingering, and treat infeasible and search-exhausted as different answers.
    
      
    
    

    
    
    
    
      
    Import full scores
    
      
    The score-import skill finds scores on the web with CloakBrowser (opens in a new tab) and converts MusicXML, MXL, ABC and MIDI into scorify scores. It keeps exact time, spelled sounding pitches, voices, ties, repeats, chord symbols and lyrics, and records where each file came from. It honors robots.txt and stops at logins, paywalls and human checks. It runs on its own with Python 3.9 or newer and no packages: let your agent drive it (install it as shown below), or call its command line. Open the result here with Open a score file… or pass it to normalizeScore().
    
      
    
    

    
    
    
    
      
    New scores with Claude Code or Codex
    
      
    The score-import skill works in Claude Code and Codex. Ask your agent for a song, and it searches the web, downloads a score, converts it and checks the result. You get a *.scorify.json file, or a *.scorify-set.json with several versions of one song, each with its difficulty. In Claude Code, the repository (opens in a new tab) is a plugin marketplace, and one command installs the skill; in Codex, the built-in skill installer fetches it from GitHub. It needs Python 3.9 or newer, and CloakBrowser for web pages. Open the file here with Open a score file….
    
      
      
    The one-step install needs Claude Code 2.1.275 or later and clones the whole repository (116 MB on disk, mostly this site's cache). From a shell, two steps work with any version and fetch only the skill (1.7 MB): claude plugin marketplace add kyr0/scorify --sparse .claude-plugin skills, then claude plugin install score-import@scorify. Updates: claude plugin marketplace update scorify. Scores are for your private practice: the skill honors robots.txt, stops at logins, paywalls and human checks, and does not transcribe audio. Its instructions: SKILL.md (opens in a new tab).

    Use scorify for ukulele and guitar arrangements in this app: https://github.com/kyr0/scorify
    
          
    Install it with npm install scorify (ESM, TypeScript declarations included). Read its README.md and docs/IMPLEMENTATION_SPEC.md first.
    
          
    Write sounding pitches with parsePitch() and exact quarter-note times with q(n, d). Build scores with createScore() and call arrange(score, { instrument, mode: "exact", player: { level } }).
    
          
    Branch on result.status: "infeasible" means proven impossible within the model, "search-exhausted" means not proven. Render result.annotations; never derive frets from pitches yourself.
