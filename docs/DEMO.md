# The docs site and playground

`docs/index.html` is the project's landing page: a live playground, how the library works, an API overview and installation instructions. GitHub Pages can serve the `docs/` folder as it is (`.nojekyll` is present).

## Build, serve and check

```sh
bun run build:docs   # build dist/ and copy it, with third-party notices, to docs/assets/scorify/
bun run dev:docs     # http://localhost:4173
bun run check:docs   # Chromium: every song arranges, draws, plays and follows the audio clock
bun run precompute:docs            # search the usual configurations again → docs/assets/cache/
bun run check:cache                # is every usual configuration cached and fresh? (replays, no search)
node scripts/precompute-docs.mjs --private   # the local practice library → work/private-scores/cache/
```

`docs/assets/scorify/` is a generated copy of `dist/`. The page imports it as native ESM, without an import map or bundler, and loads the arrangement worker from the same origin; the audio module loads on the first Play. Commit the copy when GitHub Pages serves `docs/` directly; run `build:docs` again after every library change, then `precompute:docs` (a cache made by another build is not replayed; see below).

The UI comes from [defuss-shadcn](https://github.com/kyr0/defuss-shadcn) v0.9.11, loaded from jsDelivr and pinned by Subresource Integrity. v0.9.11 is the first release with the Fretboard, Fretboard Neck and Chord Chart components; npm's `defuss-shadcn@0.9.10` does not have them. To upgrade, change the version in the four `cdn.jsdelivr.net` URLs and recompute each hash (`openssl dgst -sha384 -binary FILE | openssl base64 -A`). `check:docs` needs network access to `cdn.jsdelivr.net`, and a Chromium build that matches Playwright; set `SCORIFY_CHROMIUM_PATH` to use another. `SCORIFY_DOCS_SHOTS=dir` saves screenshots.

## What the playground shows

### Songs, one version per difficulty

The songs in `docs/assets/songs.mjs` are content for scorify's songs module (`scorify/songs`), which does all the arranging described here: chord voicing, the source of each version, imported scores and charts, version fallback, cached replay, retime and capo suggestions. The demo file holds the songs and draws the Fretboard tab. They are hand-authored accompaniments: a chord progression (symbols only) and seven versions, one for each difficulty, each with its own rhythm pattern, bass and fills. Rainbow, for example, goes from two strings strummed once a bar (baby), down strums on 1 and 3, down-up strums, the island strum with light and then full up-strokes, the island strum with sixteenth-note pushes (expert), to pushes with a melodic fill closing every phrase (maestro). Wicked Game goes from a bass note per bar to an alternating bass under treble strums with a B minor run; House of the Rising Sun from a bass note per bar to a six-note arpeggio with an alternating bass and fills.

House of the Rising Sun carries the traditional tune and its first verse (Musicaviva's ABC, converted with the score-import skill and moved to A minor). Words and sounding vocal pitches appear in separate lanes under the tab; the melody is not synthesized. The bundled Rainbow and Wicked Game studies contain accompaniment only. The local practice library described below replaces those cards with imported voice-and-piano scores, including their vocal notes and lyrics.

A pattern hit picks chord tones by string order (`0` is the lowest string the voicing plays, `-1` the highest). A bar may hold several chords sharing it evenly (`"C Am"`: two halves); a hit plays the chord sounding at its time, and `"N.C."` leaves a bar, or part of one, silent. A tone rings until its string is struck again, the next chord's first hit, a fill starts or the bar ends, less the version's `release` (the baby and beginner versions let go a quarter early, so there is time to change chords; at most half of the ringing time is given up). Every note is also released a 32nd early (`gateDuration`), so a re-struck string, a strum sweep and humanized timing never overlap. The last bar, and any bar listed in `holds`, strikes once per chord (the version's `hold` hit, else the first hit of its pattern) and lets it ring, so an easy version also ends easily.

Voicings are found per instrument and level. The demo proposes chord shapes from contiguous string runs (root or fifth in the bass on five or more strings, fretted span ≤ 3, more than four fretted notes only with a barre). It ranks them by bass, unisons, low position (nothing above the fourth fret), string count, barre, fretted notes and height, so the chord-book shape comes first (`xx0232` for D on guitar, `2223` for D7 on ukulele), then asks scorify which ones it can finger: each candidate is arranged on its own, with only the left hand limited. Every part of the chosen shapes is passed to scorify as the player's `familiarShapes`, so the solver prefers them to the same pitches elsewhere on the neck (a high-G ukulele would otherwise play G and B as the open G string and the C string's 11th fret). Versions with an alternating bass leave the shape on every bass note and are not given familiar shapes; with them, the beam lost Wicked Game's maestro chart on low-G ukulele. The version is then arranged in **exact** mode in the module worker, so every source note keeps its pitch, onset and hold. Strummed songs use `rightHand: "strum"`; the arpeggio uses `"pick"`. The tab, neck and chord charts come only from `result.annotations`. A chart shows the strings the arrangement actually plays in one hand position, the five frets that hold most of the chord's strings (`x` = not played there); a note further away, such as a run or a bass note up the neck, stays in the tab and on the neck, since the chart could not draw it. Bars that play part of the same voicing merge into one chart, and a different voicing of the same chord gets its own numbered chart. The chart of the chord sounding now moves to the front in a golden ring (defuss-shadcn shapes, `aura aura-gold`); the next chord stands right of it with a dashed border and, while playing, blinks with the beat during the bar before it comes, so the next shape can be prepared; the other charts keep their order. With reduced motion the charts do not slide and the next chord does not blink. The neck scrolls sideways to keep the sounding notes in view when it is wider than its panel. `createPerformance` adds the strum strokes (only at onsets that attack a note) and seeded humanization.

### Difficulty

The Difficulty select offers scorify's seven built-in levels, baby to maestro, and opens at maestro, 20% above the piece's tempo. They are editable policies (attack rate, notes at once, fret span, shifts, barres, shortest note, how high on the neck), not measured abilities. Each difficulty starts at the piece's own tempo, except maestro, which plays 20% faster (`LEVEL_TEMPO` and `tempoFor` in `songs.mjs`; Rainbow 80 → 96 BPM). Choosing a song or a difficulty sets that tempo; the slider's mark still returns to the piece's own tempo. The tempo is playback only: every arrangement is fingered at the piece's own tempo (see [Changing the tempo](#changing-the-tempo)). For a chosen difficulty the playground plays:

1. the version written for it, fingered in exact mode;
2. if that does not play on this instrument, the next easier version, down to the easiest;
3. if none does, the easiest version simplified by scorify's adaptive mode (ornaments and accompaniment may be left out and notes moved by an octave; the melody is kept), with the number of notes kept.

An imported score also has its chords: scorify reads a major or minor triad per beat from the notes of its hardest version (a heuristic, and About this arrangement says so) and a simpler chart with one chord per half bar. Baby strums the simpler chart on the strong beats and beginner on every beat, before any of the score's own versions; from amateur up the chords are strummed (down and up, letting go a sixteenth before each strum so the hand can move) only when nothing else plays. Canon in D reads D A Bm F#m | G D G A.

**Picked notes per bar.** When the right hand picks (imported scores, picked chart versions), a bar may pick at most 2 notes at baby, 3 at beginner, 4 at amateur, 6 at semi-pro and 8 at pro, unless each sounds alone: one note at a time is always allowed, so the limit thins notes picked together, never the tune's moments. Strummed chords do not count; expert and maestro have no such limit. When scorify simplifies, a moment of the source that keeps none of its notes costs more than leaving out several notes that start together, and in a chord of the melody voice only the top note is the melody. Canon in D's simplified ensemble keeps every moment of every bar at amateur, semi-pro and pro.

A version does not play when the source exceeds the difficulty's attack rate, notes at once or picked notes per bar at the piece's tempo (checked before any search), when the level cannot finger a chord shape, when the search proves it impossible within the model, or when the search budget runs out (which is not a proof). **About this arrangement** (below the facts) names the version that played and why each harder one did not, and the Difficulty fact reads `maestro · expert version` when a fallback was used. The notes fact compares the notes played with the hardest version as written on the same instrument, capo and settings (`hardestNotes`): Rainbow on high-G ukulele plays 768 of the local maestro version's 1,052 notes at beginner (`768 / 1052 · 73%`). A note count is not a difficulty: a strum over six strings is six notes, so an easier strummed version can play more notes than a picked maestro version (the local Wicked Game's semi-pro version plays 205% of its maestro version's notes on guitar). Notes that scorify leaves out when it simplifies show as a lower count and the `adaptive` mark; About this arrangement says how many of the version's notes were kept. Attack density counts every string a strum hits, so a slower tempo lets a lower difficulty play a strummed version. The playground never relaxes a limit or changes a fingering to make a song play.

**Search.** A beam keeps the cheapest partial fingerings and can prune the only path through a later chord change. Arrangements start with 32 states and 512 candidates per frame (at most 10,000,000 expansions). Adaptive imports with more than 300 accompaniment notes first try 8 states and 128 candidates under the same expansion cap, allowing a long score to reach its final bars sooner. An exhausted search retries the ordinary tier, then 128 and 2,048 (40,000,000), then 2,048 and 16,384 (4,000,000). These are approximate searches, and the first successful result is retained. A retry runs only after search exhaustion. The last tier lets Rising Sun's amateur to pro versions play on low-G ukulele (up to about 470,000 states, 3 seconds).

In each song's own key without capo, every version plays on every instrument as written, except:

| Song | Instrument | Difficulty | Plays instead | Why |
|---|---|---|---|---|
| Somewhere Over the Rainbow | 7- and 8-string guitar | expert | pro version | the extra strings raise the strum to 23 string attacks in a second; expert allows 20 |
| Wicked Game | concert ukulele, high G | maestro | expert version | the alternating bass and run are proved impossible within the model |

In the other eleven keys and with capo, 116 of the 5,166 configurations play an easier version and none fails: Rainbow's expert version on 7- and 8-string guitar as above, in some keys the maestro versions of Rising Sun on the guitars and of Wicked Game on most instruments (the expert version plays), and Wicked Game's amateur version on mandolin in one key. Change the songs, the chord finder or the engine and re-measure (`versionsFor`, `prepare`, `limitsExceeded` and `RETRIES` in `songs.mjs` reproduce what the page does).

### Scales and chord progressions

The library above the player has three vertical tabs (defuss-shadcn's tabs): **Songs**, **Scales** and **Chord progressions**. The page opens on Songs; the choices in the other two are remembered in this browser (`scorify-demo-library-1`).

**Scales.** A scale (major, natural, harmonic and melodic minor, major and minor pentatonic, blues, the five other modes, chromatic), one to three octaves, a time signature (4/4, 3/4, 6/8, 12/8) and notes per beat (quarters, eighths, triplets or sixteenths; in 6/8 and 12/8 dotted quarters, eighths or sixteenths). The Key select below sets the tonic, spelled as usually written for the scale (D♭ major, C♯ minor). scorify writes the scale up and down from the lowest octave the neck holds up to its highest fret, the last note held to the bar line, and fingers it for the difficulty in exact mode; with the Beat on it is a practice loop. When the scale does not fit the neck (two octaves of F major on an 18-fret high-G ukulele end on F6, beyond its D♯6), the page says so instead of moving notes; a higher highest fret, fewer octaves or another key makes it fit. A difficulty that cannot play the notes is reported (baby plays nothing shorter than a quarter note), never thinned. Scales are fingered at 60 beats a minute; the tempo slider is playback only, as for songs. They are searched in the browser, not precomputed.

**Chord progressions.** Thirteen cards, ranked by how many of 739 Billboard Hot 100 songs (1958–1991, McGill Billboard corpus) start a phrase with each: I–IV–V–I (42), I–vi–IV–V (28), I–IV–I–V (28), I–V–IV–I (23), the 12-bar blues (23 songs with a 12-bar blues chorus), I–♭VII–IV–I (22), I–V–I–IV (18), I–vi–ii–V (17), I–V–IV–V (12), I–♭III–IV–I (12), I–V–vi–IV (7: the corpus ends before it became common), i–♭VI–♭VII–i (5) and i–♭VII–♭VI–V (4). These are every progression that starts on the tonic in at least 12 songs, plus I–V–vi–IV and the most common minor ones; `scripts/billboard-progressions.py` counts them from the corpus. Each card shows its chords in the key on show. A progression plays a bar per chord, twice (the blues once), and ends on the tonic, in seven versions for its time signature (4/4, 3/4, 6/8, 12/8); the Key select moves it, and difficulty, capo suggestions and fallbacks work as for songs. Progressions are searched in the browser.

### Imported scores

`docs/assets/scores/greensleeves.scorify.json` was made with the score-import skill from a public-domain MIDI of the Greensleeves hymn tune (SATB on two staves, `--pickup 1/2`); `notation.source` keeps its checksum and retrieval date. **Open a score file…** adds `.scorify.json` files and score sets (`*.scorify-set.json`, several versions of one piece, each with its difficulty; see the skill's `references/FORMAT.md`) the same way. Files never leave the browser; the last twelve opened are remembered in `localStorage` (`scorify-demo-opened-scores`) and come back as cards on the next visit.

A score set's versions are chosen by difficulty as above. A single score is one version whose difficulty is estimated from its attack rate and notes at once, and it is marked "(estimated)".

An imported score is moved by whole octaves into the instrument's range. It uses adaptive mode (octave shifts and dropped accompaniment allowed, melody preserved) only when notes still fall outside the range or more notes sound at once than the instrument has strings. The status line lists every change:

- **Sung parts.** Parts listed in `notation.vocal` (parts with words, or named like a voice) are shown, not played: one lyrics lane per verse under the tab (`notation.lyrics`, then `notation.verses`), plus a **Voice** lane containing each sounding pitch with its octave, exact onset and duration. Lyric holds stop at rests. `notation.lyricLanguages` optionally labels each verse's language. The other parts are arranged; The notes fact leaves the sung notes out of the count. A score that is nothing but a sung part is played as written. This is a timed pitch display, not staff notation or a synthesized singer.
- **Voices.** When a score has inner voices, the Voices control offers all voices, melody and bass (the default), or melody only. Notes left out are counted, and the notes fact compares against the whole file.
- **Articulation.** Notation exports hold every note until the next attack, which leaves the fretting hand no time to move. Notes that end exactly where another starts are released a 32nd early, as in the songs; pitches and onsets stay exact.
- **Pickups.** A short first meter is drawn as a pickup, so the tab's bar lines match the score.

Greensleeves with all voices (235 notes) plays as written on the guitars at expert and maestro; amateur to pro play it simplified to their picked notes per bar (83, 100 and 132 notes), on the ukuleles and mandolin too. On the ukuleles and mandolin, expert and maestro, which have no such limit, cannot hold all four voices: the search runs out of budget (proved impossible as written on mandolin) and they strum the amateur chord version. The cache answers at once; a search of its own takes about 40 seconds for each attempt. Melody and bass plays on every instrument.

### Local practice library

`bun run dev:docs` also reads the optional, ignored `work/private-scores/index.json`. Each entry names an `id`, a score `file` in that directory and an `instrument`, for example `{ "id": "rainbow", "file": "somewhere-over-the-rainbow.scorify.json", "instrument": "guitar" }`. Matching IDs replace the sample cards; other IDs add cards. They reload from disk on every visit without copying into localStorage.

An entry may also name a `chart` (`*.chart.json`, schema `scorify-chart-1`): a chord chart written for that score's bars. The card then plays the chart, not the score's accompaniment parts: seven strummed versions, baby to maestro, like the songs above, under the score's sung part, its words (every verse) and its tempo map, ritardandos included. Fretted players accompany a singer from the chords; a piano part moved by octaves and thinned out for an easier level is neither the song's sound nor easier to play. A chart has a `progression` with one entry per score bar, an optional `simpleProgression` that versions marked `simple` play (plain major and minor triads for the easier versions), `holds`, an optional default `bpm` (the score's tempo map is scaled to it), the versions, and optionally `vocalTranspose` (`[{ bars: [first, last], interval, reason }]`), which moves a sung passage that the edition wrote in another key than its accompaniment; its reason is shown with every arrangement. Each version is fingered in exact mode, as written; it is never simplified by octave shifts or dropped notes. A version that only strums may set `countStrokes`: a strum is one movement of the hand, so the difficulty's attack rate limits strokes rather than strings. The page then passes scorify an explicit `maxAttacksPerSecond` override of that rate times the instrument's strings, checks the stroke rate before searching, and says so under About this arrangement; scorify's per-string limit itself is unchanged, and the songs above still count every string. Without it a beginner (4 attacks a second) could strum a four-string chord once a second at most. `songFromChart` checks that the chart has as many bars as the score and only chord symbols the chord finder knows.

The local server injects a library reference into the served page and exposes only manifest-listed JSON files, and the library's precomputed cache (`work/private-scores/cache/`, made with `node scripts/precompute-docs.mjs --private`), through a loopback-only, uncached route. Originals, metadata and checks remain in `work/private-scores/`; they are not copied by `build:docs`, included in the npm package, or served by static hosting. The normal `check:docs` exercises the public examples independently of this optional library. `node scripts/check-private-docs.mjs` checks the installed private library, comparing every displayed vocal pitch (after a chart's documented `vocalTranspose`), onset, duration and lyric to the imported files, exercising playback, and saving a report and screenshots beside them. For a chart it also checks that the accompaniment is strummed, that silent bars read N.C. and play nothing, and that every difficulty arranges in exact mode, recording which version played.

### Cached arrangements

The usual configurations are searched in advance: every piece on every instrument at every difficulty in each of its twelve keys, with each choice of voices of an imported score (Greensleeves: all voices, outer voices, melody only), with and without its suggested capo (5,502 for the public pieces, 62 MB gzipped; the local library has its own cache, 6,788 configurations and 311 MB). `scripts/precompute-docs.mjs` runs the page's own `arrangeFor` in Node worker threads and writes each run's log, gzipped, to `docs/assets/cache/<key>.json.gz`, with `index.json` listing them. The key fingerprints the request (piece, instrument, difficulty, key, voices, capo, custom settings; not the tempo, see below). Each attempt in the log carries a second fingerprint of its inputs: the prepared source, the options (instrument, player, mode, search) and the cache version (`src/VERSION`, which `build:docs` writes to `docs/assets/scorify/build.mjs`). The version is set by hand: change it when a library change should search every cached configuration again. Library changes that leave it alone (the audio, say) keep the cache.

The page looks for a request's log in memory, in IndexedDB (`scorify-demo`, the last 80 searched in this browser, each stored with the cache version that searched it) and in the precomputed files, and replays from all three together, so a result this browser searched under an earlier cache version can neither hide a fresh precomputed one nor be replayed itself (entries of other versions are pruned). It replays an attempt only when its input fingerprint matches what the page would search now, and first checks the replayed fingering with scorify's independent `validateFrettedArrangement`; anything else is searched as before. A stale or damaged cache therefore costs time, never correctness; a replay under an unchanged version after a search change may be less good than a new search, never outside the difficulty's limits. Replayed arrangements say so under About this arrangement ("Replayed from the precomputed cache, without a search") and in the Search fact (`· cached`); the performance is compiled and validated as usual. Measured in headless Chromium: the first song draws 131 ms after the page settles, another cached song in about 75 ms. Fingerprints are cache keys (cyrb53, 106 bits), not a security measure: a page only replays results it then validates.

`bun run check:cache` replays every cached configuration with a search that throws, and fails if any attempt would have to be searched. Changing a song, the chord finder, `prepare`, a difficulty's limits or `src/VERSION` makes the affected entries stale; run `precompute:docs` again. It keeps entries that still replay completely and searches only the others; it spreads the searches over all but two CPU threads (a full run after a cache version change: 3¼ CPU-hours of search for the public pieces, 13½ minutes on 16 threads; 23½ CPU-hours and 88 minutes for the local library, most of it Bamboléo); `JOBS` sets the thread count. Files no configuration uses any more are removed.

### Changing the tempo

The tempo is playback only. Every arrangement is searched and validated at the piece's own tempo (`arrangeFor` in scorify's songs module), whatever the slider says; the slider, and maestro's 20%, scale the arrangement's tempo map (`retime`) and never start a search. About this arrangement says so when they differ ("Fingered at the piece's tempo, 80 BPM; 96 BPM changes playback only"). scorify's time-based limits (string attacks in a second, how fast the hand shifts, finger setup) are therefore judged at the piece's tempo only: every take is performed with `timeLimits: false` (`createPerformance`), which lifts them and records it in the plan, so no tempo stops a fingering from playing; a much faster playback can exceed what the difficulty allows. The fingering itself and every other check of the performance still apply. The cache key leaves the tempo out. A new tempo keeps the place: playback goes on from the same beat without a count-in, a pause stays where it was, and a loop of bars is kept.

**High on the neck.** Every difficulty below maestro prefers low positions (scorify's `highFretCosts`): baby to semi-pro strongly prefer frets 0–8 and go above fret 10 only rarely, pro and expert only avoid frets above 10, maestro plays anywhere the neck allows. Frets count from the capo, as the tab shows them. It is a cost on the fingering, never a reason to leave a note out: a note that lies only above fret 10 is played there, and when the search runs out of budget with the preference it searches again without it (About this arrangement says so).

**Highest fret.** The slider next to Tempo is the instrument's highest fret, a hard limit: the ukuleles' usual 18, the guitars' 19, the mandolin's 20 (marked "usual" under the track; a click on the mark brings it back), from 5 to 24. Another value searches again (the cache holds the usual neck), says "Frets up to 12 only" in About this arrangement, and is remembered for that instrument in this browser (`scorify-demo-necks-1`). A capo above the highest fret is reported instead of played. Custom mode's **Player's highest fret** is the player's own limit (`maxFret`), counted from the nut.

### Key

The Key select next to Difficulty moves the piece from a tritone down to a fourth up (−6 to +5 semitones), named by its key (`Eb major · +1`). A chord song's chords and sung pitches move and its chord shapes are found again; an imported score moves by the interval, then by whole octaves into the instrument's range. The capo suggestion follows the new key. Every key is precomputed for every instrument and difficulty. Custom mode's own transposition, when set, wins over the select.

### Capo

For a chord song the page suggests a capo when one makes the chords easier to hold, and offers it as a checkbox, for example **Capo on fret 2 · Am G D shapes** for Wicked Game in B minor on guitar. The song keeps its key: a capo shortens every string, so the same sounding chords are fingered as lower shapes, here Bm, A and E as Am, G and D.

A capo is not a renumbering of the tab. Open strings sound behind it, so the shapes, the strings they use, the bass note and the possible voicings all change, and a different chord may be the hardest one. Toggling it therefore asks for another arrangement. To make the toggle immediate, both sides of usual configurations are precomputed, and while one side shows the other is searched (or replayed) in a second worker. In the browser check the toggle takes about a millisecond. With the capo on, the chord names in the tab and charts are the shapes fingered (Am G D), the facts and the tab title name the capo, and the frets in the tab count from the capo, as players read them. Sounding pitch, note spelling and timing do not change; scorify's instrument keeps both absolute and capo-relative frets.

`suggestCapo` (in `songs.mjs`) rates each fret up to the fifth (the seventh on six or more strings) with the chord finder's first shape for every chord, judged whole as in a chord book: an open chord (an open string, nothing above the third fret, no barre) costs 1, any other shape 3, a barre 4, weighted by how long the chord sounds. A capo is suggested only when it leaves fewer chords that are not open chords and costs no more; ties go to the lower fret. It is a heuristic about chord shapes, not a measured playability gain, and the suggestion still has to arrange like any other. Imported scores without a chart and custom tunings get no suggestion. Measured: Wicked Game (B minor) gets capo 2 on every instrument; the public Rainbow and Rising Sun get none; the local library's Rainbow gets capo 5 (G-shapes) on guitar and baritone ukulele for its colour-chord versions, semi-pro and up.

### Custom mode

The collapsible **Custom mode** section sets what the page otherwise chooses, and **Re-compute score** searches with it:

- **Arrangement:** a version (any difficulty's), a mode (versions only as written, adaptive simplification of the chosen one, or the default of versions then simplification), and a transposition in semitones. Transposing changes the chord symbols, the key and the sung pitches (spelled without double accidentals, E♯, B♯, C♭ or F♭) and finds the voicings again; it does not shift a fingering.
- **Instrument:** a capo fret (replacing the suggestion) and a tuning, sounding pitches from the bass edge.
- **Player limits:** scorify's player overrides on top of the chosen difficulty: fret span, shift speed, string attacks per second, notes at once, highest fret, barre chords, right hand; and the complexity and flexibility used when simplifying. Empty fields keep the difficulty's values, which appear as placeholders.
- **When simplifying:** scorify's adaptation permissions.
- **Search:** the strategy (beam or exact dynamic programming), beam width, candidates per frame and the expansion budget. Custom search settings run as given, without the wider retries.
- **Playback:** the human feel and a fixed take seed.

Custom settings stay in force for every song, instrument and difficulty until **Reset to the difficulty**. They are hard constraints like the difficulty's: a version that no longer plays is reported, and the next easier one is tried. The mode badge reads "Custom ·", About this arrangement lists the custom limits, and a chart's `countStrokes` override is not applied when a custom attack rate is set. Settings scorify rejects (an unknown pitch in a tuning, for example) are reported in place of a result.

**Export** saves the shown arrangement as `*.arrangement.json` (schema `scorify-arrangement-1`): the request, the custom settings, the piece it was made for (a built-in song by id, or the whole opened score or chart) and the log with the result. **Save in this browser** keeps it in IndexedDB, listed under Saved arrangements with Open, Export and Delete. **Import…** (or **Open a score file…**) opens an exported file: it restores the song, instrument, difficulty, tempo and settings, and replays the saved result after validating it again, so an edited file cannot put an unplayable fingering on the page.

### Sound effects and printing

Play is defuss-shadcn's round Play Button (a CSS triangle, two bars while playing; defined in `site.css` because the pinned release does not ship it yet), its name read as Play, Pause or Resume. Right of Play, Stop, WAV and Print, three switches add scorify's post effects (`scorify/audio-effects`, see [AUDIO.md](AUDIO.md#post-effects)): **Tape delay** (a dotted eighth at the current tempo), **Reverb** and **Saturation** (soft), all on by default. Playback runs through the library's effects AudioWorklet (`createEffectsNode`), so a switch takes effect within 20 ms while a song plays and a delay or reverb switched off rings out; the WAV is rendered with the same chain (`renderPerformance(…, { effects })`), so it sounds like the playback. The switches are remembered in this browser (`scorify-demo-effects-2`; a new key, so choices saved before the defaults changed do not hide them). The tuner's reference pluck stays dry.

**Practice.** Between Print and the effects, a **No loop / Loop** swap (defuss-shadcn's swap, flipping between its two faces) and two switches. **Voice** sings the piece's sung part with scorify's guide voice (`renderGuideVoice` in `scorify/audio-guide`, at the Voice lane's pitches: four soft partials, a late vibrato, a 1.8 kHz lowpass; on by default, disabled for a piece without a sung part). **Beat** (on by default) adds a metronome: a kick on the strong beats and a clap between them (`renderClicks` and `clickPattern`: 4/4 kick, clap, kick, clap; 3/4 kick, clap, clap; 6/8 on its dotted pulses), the sounds of defuss-shadcn's envelope compressor demo, compressed and kept quiet; it follows the tempo map, ritardandos included, and skips a pickup's silent padding. Both are rendered with every segment of the strings and switched by a gain, so they take effect at once; the voice sings through the effects, the metronome stays dry. The WAV includes what is switched on, without the count-in. The switches are remembered in this browser (`scorify-demo-practice-2`).

Playback from a stop or a pause counts in one bar: the clicks of the bar before the bar line it starts on (from inside a bar, the next one; a pickup falls into the count-in's last beats), at the tempo there, heard whether or not the metronome is on, while the playhead waits at the start. Jumping to a measure while playing, and a loop's next pass, do not count in. The count-in is playback only: the tab, the print view and the WAV leave it out. With **Loop**, the song starts again from its first bar when it ends, as a new take and without a count-in; switching it while playing takes effect from the next rendered segment. A loop of bars in the tab takes precedence.

**Print** shows a print view and opens the browser's print dialog: the title, a line with the credit, instrument (capo, tuning), difficulty and version, tempo, meter and key, then the tab itself laid out at page width (bar numbers, chord names, frets, strums, words and the voice's pitches), and every chord chart of the arrangement below it, static. Lines of the tab do not break across pages; chord diagrams print with their grid and dots (`print-color-adjust: exact`). The page prints light in either theme. **Close print view** or Escape returns; the browser's own print without the button prints the page as it is.

### Tuner

Above the player, a tuner listens through the microphone (after **Listen**, and the browser's permission). `scorify/tuner` feeds it to the pitch-detector AudioWorklet (YIN) over the range of the instrument chosen below, from a fifth under its lowest string to a fifth over its highest, and reconfigures it when the instrument changes. Each reading is matched to the nearest string, or to the string picked with the buttons, and shown on the defuss-shadcn tacho (`tacho.tune` with that one string): note, frequency and cents, green within 5 cents, with a line saying which string is sharp or flat. After about half a second without a clear pitch the dial rests. **Play the string** plucks the picked (or last heard) string with scorify's synth as a reference. Stopping releases the microphone. The page needs a secure context for the microphone; a refused permission or a missing microphone is explained under the dial.

### Playing

The feel is fixed and not shown as a control: a loose human feel, `humanize` 0.8. Strums are centered on their beat and sweep at a speed set by the tempo; dynamics follow the bar, the melody and bass, and the strum direction; strings drift by less than a cent (see [AUDIO.md](AUDIO.md)). The facts and About this arrangement describe a reference take with a fixed seed. The line under the transport shows only progress (a search, its retries) and problems; the page shows no playback clock, the tab's playhead shows where the song is.

Every playback is a fresh take: `createPerformance` with a new seed, validated like the reference, so no two playbacks sound the same. It is rendered offline (`renderPerformance`, the same samples the AudioWorklet player makes) in segments played by `AudioBufferSourceNode`s, each queued while the one before plays, with an 8 ms crossfade: six-second pieces of one take, so playback starts at once, and in a loop a new take for every pass, so every pass is new. The playhead's clock follows each scheduled segment, so it stays with the sound across loop passes. Each segment includes four seconds of earlier notes, so strings that are already ringing carry into it. Playback and loops start 50 ms before the bar line, so the early strings of a centered strum are heard; the playhead shows the bar line.

The tab is the transport: its play button, Space (when nothing else has focus), a click on a measure and a loop all go through the tab's `setState`, which the page wraps so they make sound, and the AudioContext clock moves the playhead. Play becomes Pause while playing and Resume after a pause, and continues where it stopped (as a new take); Stop rewinds. The bar numbers are the loop header: a click loops that bar (Shift-click extends it), a drag forward along the numbers loops the bars it covers, and a double click or a drag back clears the loop. At the end of a song the playhead holds at the end while the last notes ring out, then returns to the start once (the tab component's own clock would otherwise reset it while the page still moved it). The tempo slider marks the piece's original tempo; clicking the mark goes back to it. Changing the song, instrument, difficulty, key or highest fret stops playback; a new tempo keeps the place. The **WAV** button renders a new take at 44.1 kHz.

The Key select and Custom mode's transposition move the piece, not an arrangement's frets: shifting these strummed voicings along the neck mostly ends in `search-exhausted` or high up the neck, so a chord song's chord symbols move and its voicings are found again, as a player would. The install section shows the library's transposition and adaptation API.

## Checks

`check:docs` clicks every piece in light and dark mode: each must arrange at maestro (20% above its tempo) as the version written for maestro, keep its notes, draw a tab and neck and, in light mode, play while the tab follows the audio clock. In light mode it also checks Play, Pause and Resume (resuming where it paused), Space, a loop on measure 3 that wraps with sound and performs a new take on every pass, and the loop header: a double click clears the loop, a drag forward loops two bars, a drag back clears them, a click loops one bar. It drives the tuner with a synthetic microphone stream: the strings of guitar and ukulele, the nearest string heard, +30 and −8 cents, in tune within 5 cents, a picked string, reconfiguration on an instrument change, and the microphone released on stop. It checks that the active chord leads the voicings in a golden ring with the next chord second and blinking, that the song ends with exactly one jump back to the start, that a narrowed neck keeps every sounding note in view, and that the original-tempo mark restores the tempo.
